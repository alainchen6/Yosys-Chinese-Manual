数据流跟踪
----------


借助 *数据流跟踪* 支持，Yosys 可用于回答诸如“这个信号会影响另一个信号吗？”
之类的问题。为此，需要向设计中插入四种特殊单元——`$get_tag`、`$set_tag`、
`$overwrite_tag` 和 `$original_tag`（例如由自定义 Yosys pass（处理流程）插入），
然后运行 `dft_tag`，它会把这些单元转换为普通逻辑。通常随后会使用 `SBY`_ 来
证明涉及这些单元的断言。

.. _SBY: https://yosyshq.readthedocs.io/projects/sby

在 Yosys 中，位的状态通常就是 ``0`` 或 ``1``（或特殊值 ``z`` 和 ``x``）。在
数据流跟踪过程中，这些状态会附加一组标签。例如，某一位的状态可以是 ``0``，标签
集为 ``"KEY"`` 和 ``"OVERFLOW"``。

除了对逻辑位执行通常的运算外，Yosys 操作现在还必须处理标签的状态。为此，标签会
按照以下通用规则简单地从输入向输出 *转发* 或 *传播*，即复制：

   当输入在其余所有输入的特定状态下能够影响输出时，该标签就会从该输入转发到
   输出。

例如，XOR、AND 和 OR 单元按如下方式传播标签：

#. XOR 直接把其输入上的所有标签转发到输出，因为 XOR 的输入总能影响输出。
#. AND 只有在另一个输入为 ``1`` 时才转发某个输入上的标签。因为如果有一个输入为
   ``0``，另一个输入就永远无法影响输出。
#. 类似地，OR 只有在另一个输入为 ``0`` 时才转发标签。

该规则有两个例外：

#. 一般而言，传播只是近似确定的。例如，除非 ``dft_tag`` 代码了解某个单元，否则
   它只会假设最坏情况，即所有输入都能影响所有输出。此外，该代码也没有考虑：当
   一个信号影响某个单元的多个输入时，由此产生的输入同时变化可能相互抵消。例如
   ``A ^ A`` 或 ``A ^ (B ^ A)`` 与 ``A`` 无关，但它们的标签仍会被传播。
#. 如果使用了标签组，规则会有所修改（见下文）。

由于这种传播行为，要回答“哪些信号受某个信号影响”的问题，我们可以在电路中该
信号处注入一个标签，并观察标签在哪些地方可见。

示例用例
~~~~~~~~


作为一个示例用例，考虑一个不应向外界泄露密钥的密码处理器。我们可以给所有密钥位
打上 ``"KEY"`` 标签，并使用 `SBY`_ 形式化验证没有任何外部信号携带 ``"KEY"``
标签，也就是说密钥信息对外不可见。需要注意，我们必须在密码运算期间手动清除
``"KEY"`` 标签，因为证明密码运算本身不会泄露密钥信息超出了 Yosys 的能力。不过，
我们仍然可以轻松检测出例如某位工程师忘记删除允许读回密钥数据的调试代码的情况。

作为另一个用例，我们可以修改设计中的所有加法器，在加法溢出时给它们的输出位打上
``"OVERFLOW"`` 标签，然后为所有触发器输入和输出信号添加断言，声明它们不携带
``"OVERFLOW"`` 标签，即溢出加法的结果永远不会影响系统状态。注意，在这个特定
示例中，我们利用了标签插入可以以逻辑为条件的能力，这里的条件是加法器的溢出条件。

数据流跟踪单元的语义
~~~~~~~~~~~~~~~~~~~~


``$set_tag`` 具有输入 ``A``、``SET``、``CLR``，输出 ``Y`` 以及字符串参数
``TAG``。``A`` 的逻辑值以及除 ``TAG`` 参数所指定标签之外的所有标签都会被直接
复制到 ``Y``。如果 ``SET`` 为 ``1``，则把指定标签添加到 ``Y``。否则，如果
``CLR`` 为 ``1``，则移除该指定标签。否则标签保持不变，即如果它出现在 ``A`` 中，
就出现在 ``Y`` 中。

``$get_tag`` 具有输入 ``A``、输出 ``Y`` 以及字符串参数 ``TAG``。``$get_tag``
检查 ``A`` 中是否存在指定名称的标签，如果存在就把 ``Y`` 置为 ``1``。``A`` 的
逻辑值被完全忽略。

``$overwrite_tag`` 的功能与 ``$set_tag`` 类似，但没有 ``Y`` 输出。它不是提供
输入信号的修改版本，而是“原地”修改信号 ``A``，也就是说，如果某个信号作为
``$overwrite_tag`` 的输入，则等价于在其驱动源与它所连接的所有单元之间插入一个
``$set_tag``。``$overwrite_tag`` 的主要用途是为模块内部产生的信号添加标签，而
该模块本身无法或不应被修改。

``$original_tag`` 的功能与 ``$get_tag`` 完全相同，但会忽略
``$overwrite_tag``，也就是说，在按上述方式把 ``$overwrite_tag`` 转换为
``$set_tag`` 时，它等价于把 ``$get_tag`` 插入到 ``$set_tag`` *之前*。

标签组
~~~~~~


标签组是一种高级特性，用于修改上文讨论的传播规则。要使用标签组，只需按
``"group:name"`` 的模式命名标签。例如 ``"key:0"``、``"key:a"``、``"key:b"``
将是 ``"key"`` 组中的三个标签。

此时传播规则增加如下内容：

   对于同一组的标签，输入之间不能相互阻止对方标签的传播。

例如，如果另一个输入为 1 或携带同一组的标签，AND 门就会传播某个输入上的给定
标签。因此，如果一个输入是 ``0, "key:a"``，另一个是 ``0, "key:b"``，结果将是
``0, "key:a", "key:b"``，而不是简单的 ``0``。注意，如果我们给第一个输入添加
一个无关的 ``"overflow"`` 标签，它仍然不会被传播。
