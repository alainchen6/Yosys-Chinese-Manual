ABC 工具箱
==========


.. role:: yoscrypt(code)
   :language: yoscrypt

ABC_ 是由加州大学伯克利分校开发的逻辑工具箱，用于细粒度优化和 LUT 映射。

Yosys 有两个不同的命令都使用这个逻辑工具箱，但使用方式不同。

`abc` pass（处理流程）既可用于 ASIC 映射（例如 :yoscrypt:`abc -liberty`），也可用于
FPGA 映射（例如 :yoscrypt:`abc -lut`），但本页重点介绍 FPGA 映射。

`abc9` pass 通常能提供更优的映射质量，因为它能感知组合盒子以及 DFF 和 LUT 的时序，
从而对映射问题有更全局的视角。

.. _ABC: https://github.com/berkeley-abc/abc

ABC：单位延迟模型，简单而高效
-----------------------------


`abc` pass 使用一种高度简化的 FPGA 视图：

- FPGA 由一个输入网络构成，这些输入通过 LUT 连接到输出网络。这些输入实际上可能是
  I/O 引脚、D 触发器、存储器块或 DSP，但 ABC 并不知道这一点。
- 每个 LUT 的输入到输出之间都有 1 个单位的延迟；这对 LUT 的所有输入都成立，并且
  对直到允许的最大 LUT 尺寸的所有 LUT 尺寸都成立；例如，LUT2 的输入到其输出的延迟
  与 LUT6 的输入到其输出的延迟相同。
- LUT 可能占用不同数量的面积单位。对于每种 LUT 尺寸，这个数量是固定的；例如，
  LUT4 可能占用 1 个面积单位，而 LUT5 可能占用 2 个面积单位，但这对所有 LUT4
  和 LUT5 都成立。

这被称为“单位延迟模型”，因为每个 LUT 使用一个单位的延迟。

从这个视角看，ABC 需要解决的问题是：找到一种把网络映射到 LUT 的方案，使延迟最低，
然后在保持该延迟的前提下针对面积优化映射。

这种方法有优点：

- 简单且易于实现。
- 以单位延迟进行计算时，操作速度很快。
- 它反映了 *某些* FPGA 系列的情况，例如 iCE40HX/LP 就相当符合单位延迟模型的假设
  （除加法器外几乎都是同步块）。

但这种方法也有缺点：

- 输入和输出网络只包含 LUT，这意味着许多组合单元（乘法器和 LUTRAM）对单位延迟
  模型不可见，因此它优化的关键路径不一定是实际的关键路径。
- LUT 被实现为多路复用器树，因此结果在剩余多路复用器中传播会带来延迟。这意味着
  “延迟相等”的假设在物理硬件中并不成立，而且 LUT 越大，这种延迟按比例也越大。
- 即使是同步块也有到达时间（时钟边沿到输出变化之间的传播延迟）和建立时间（输入在
  时钟边沿之前必须保持稳定的要求），这些都会影响路径的延迟。

ABC9：广义延迟模型，真实而灵活
------------------------------


ABC9 使用更详细、更准确的 FPGA 模型：

- FPGA 由一个输入网络构成，这些输入通过 LUT 和组合盒子连接到输出网络。这些盒子
  指定了输入到输出之间的延迟，并且可以带有关联网络（“白盒”）或不带（“黑盒”），
  但必须作为一个整体来处理。
- 每个 LUT 的输入到输出之间都指定了延迟，单位为任意延迟单位；该延迟对 LUT 的
  所有输入各不相同，对每种 LUT 尺寸也不同，但同一种 LUT 尺寸的关联延迟相同；
  例如，输入 A 到输出之间的延迟在 LUT2 和 LUT6 之间不同，但对所有 LUT6 都是恒定的。
- LUT 可能占用不同数量的面积单位。对于每种 LUT 尺寸，这个数量是固定的；例如，
  LUT4 可能占用 1 个面积单位，而 LUT5 可能占用 2 个面积单位，但这对所有 LUT4
  和 LUT5 都成立。

这被称为“广义延迟模型”，因为它把延迟推广到了任意延迟单位。ABC9 实际上并不关心你
在这里使用什么单位，但 Yosys 的约定是皮秒。注意这里引入了盒子这一概念。广义延迟
模型并不要求使用盒子，但盒子可以自然地融入其中，用来表示组合延迟。即使是到达时间和
建立时间这样的同步延迟，也可以用充当延迟的组合盒子来模拟。这一点进一步扩展到白盒：
映射器能够看到盒子内部，并删除没有输出的孤立盒子，例如加法器。

同样，ABC9 会找到一种把网络映射到 LUT 的方案，使延迟最低，然后将其最小化以获得
最低面积，但它可用的网络信息要多得多。

由此带来的结果是：ABC9 可以删除盒子（例如加法器）以减小面积，围绕这些盒子进行
更好的优化，还可以置换输入，把最快的输入分配给关键路径。

为 ABC9 搭建流程
----------------


大部分配置来自 Verilog 仿真模型中的属性和 ``specify`` 块。

``specify`` 语法
~~~~~~~~~~~~~~~~


由于 ``specify`` 是 Verilog 标准中相对冷门的一部分，这里给出语法的快速指南：

.. code-block:: verilog

   specify                           // begins a specify block
     (A => B) = 123;                 // simple combinational path from A to B with a delay of 123.
     (A *> B) = 123;                 // simple combinational path from A to all bits of B with a delay of 123 for all.
     if (FOO) (A => B) = 123;        // paths may apply under specific conditions.
     (posedge CLK => (Q : D)) = 123; // combinational path triggered on the positive edge of CLK; used for clock-to-Q arrival paths.
     $setup(A, posedge CLK, 123);    // setup constraint for an input relative to a clock.
   endspecify                        // ends a specify block

按照约定，``specify`` 块中的所有延迟都以整数皮秒为单位。包含 ``specify`` 块的文件
应当使用 `read_verilog` 的 ``-specify`` 选项读取，以免这些块被跳过。

LUT
^^^

LUT 需要标注 ``(* abc9_lut=N *)`` 属性，其中 ``N`` 是该 LUT 模型的相对面积。例如，
如果某个架构可以组合 LUT 以产生更大的 LUT，那么组合后的 LUT 应具有越来越大的
``N``。反之，如果某个架构可以把较大的 LUT 拆分成较小的 LUT，那么较小的 LUT 应具有
较小的 ``N``。

LUT 通常用从 LUT 输入到 LUT 输出的简单组合路径来描述。

DFF
^^^

DFF 应标注 ``(* abc9_flop *)`` 属性，但 ABC9 对此有一些具体要求才能使其有效：
- DFF 必须初始化为零（可考虑使用 `dfflegalize` 来确保这一点）。
- DFF 不能有任何异步复位/置位（关于此时该怎么办，参见简化惯用法和“盒子”一节）。

值得注意的是，在纯 ``abc9`` 模式下，只有建立时间和到达时间会传给 ABC9（具体来说，
它们被建模为具有给定延迟的缓冲器）。在 ``abc9 -dff`` 模式下，触发器本身会传给
ABC9，从而允许进行时序优化。

一些厂商的通用 DFF 模型即使在未使用时也会包含异步置位/复位。因此存在 *简化惯用法*
来处理这种情况：使用 ``techmap`` 文件找出那些异步控制端由常量驱动的触发器，把它们
映射为符合 ``(* abc9_flop *)`` 的中间简化触发器，经过 `abc9` 处理，然后再映射回
原来的触发器。`synth_intel_alm` 和用于 PolarPro3 的 `synth_quicklogic` 就采用了
这种做法。

DFF 通常被指定为：对输入信号相对于时钟具有建立时间约束，并为 ``Q`` 输出指定
到达时间。

盒子
^^^^

“盒子”是一块纯组合的硬逻辑。如果该逻辑对 ABC9 可见，它就是“白盒”，否则就是
“黑盒”。进位链最好实现为白盒，而 DSP 最好实现为黑盒（乘法器过于复杂，不易处理）。
LUT RAM 也可以实现为白盒。

可以说，盒子是 ABC9 相对于 ABC 的最大优势：通过感知进位链和 DSP，它避免针对并非
实际关键路径的路径进行优化；而通常更长的路径又使 ABC9 能够把其他逻辑映射到速度较
慢但逻辑密度更高的单元上，从而减小设计面积。
