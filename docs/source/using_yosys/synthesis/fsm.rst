FSM 处理
========


`fsm` 命令识别、提取、优化（重新编码）并重新综合有限状态机（FSM）。它同样是一条
宏命令，会调用一系列其他命令：

   :caption: `fsm` 调用的 pass（处理流程）

另见 :doc:`/cmd/index_passes_fsm`。

FSM 检测和提取所用的算法受到了文献中报道的一种更通用技术的影响

FSM 检测
~~~~~~~~


`fsm_detect` pass 识别 FSM 状态寄存器。它会在符合以下描述的任意
（多位）信号线上设置 ``fsm_encoding = "auto"`` 属性：

-  尚未具有 ``fsm_encoding`` 属性。
-  不是所属模块的输出。
-  由单个 `$dff` 或 `$adff` 单元驱动。
-  该 `$dff` 或 `$adff` 单元的 ``D`` 输入由一个多路复用器树驱动，该树的叶子只有
   常量或旧的状态值。
-  状态值只在上述多路复用器树中使用，或者只由把状态值与常量进行比较的简单关系单元
   使用（通常是 `$eq` 单元）。

这种启发式方法已被证明效果很好。可以通过在应被视为 FSM 状态寄存器的寄存器上设置
``fsm_encoding = "auto"``，并在符合上述条件但不应被视为 FSM 状态寄存器的寄存器上
设置 ``fsm_encoding = "none"``，来覆盖这一判断。

但请注意，若把不适合 FSM 重新编码的状态寄存器标记为 ``fsm_encoding``，可能会
导致综合失败或产生无效结果。

FSM 提取
~~~~~~~~


`fsm_extract` pass 作用于所有标有（``fsm_encoding != "none"``）属性的状态信号。
对每个状态信号，会确定以下信息：

-  状态寄存器

-  如果状态寄存器使用异步复位，则为异步复位状态

-  状态转移函数中使用的所有状态和控制输入信号

-  由状态信号和控制输入计算出的控制输出信号

-  所有状态转移及对应控制输入和输出的表格

状态寄存器（以及适用时的异步复位状态）只需通过找出状态信号的驱动源来确定。

然后，递归遍历驱动状态寄存器输入的 `$mux`\ 树。所有选择输入都是控制信号，
`$mux`\ 树的叶子就是各个状态。如果发现某个非常量叶子不是状态信号本身，算法就会
失败。

控制输出列表以状态信号中的各位初始化，然后通过加入所有由把状态信号与常量值进行
比较的单元计算出的值来扩展。

在大多数情况下，这会覆盖状态寄存器的所有用途，从而使状态编码变得任意。但如果设计
例如直接用状态值的某一位驱动控制输出，那么状态信号的这一位就会被转换为取值相同的
控制输出。

最后，生成 FSM 的转移表。这通过使用 ConstEval C++ 辅助类（定义在
kernel/consteval.h 中）完成，该类可用于对设计的一部分求值。可以要求 ConstEval 类
使用一组信号取值赋值来计算给定的结果信号集合。它还可以接收一个停止信号列表：如果
在计算结果信号时需要用到某个停止信号的值，ConstEval 算法就会中止。

`fsm_extract` pass 按以下方式使用 ConstEval 类来创建转移表。对每个状态：

1. 为包含该 FSM 的模块创建一个 ConstEval 对象
2. 把所有控制输入加入停止信号列表
3. 把状态信号设为当前状态
4. 尝试对下一个状态和控制输出求值
5. 如果第 4 步未成功：

   -  把导致失败的停止信号设为 0，递归执行第 4 步。
   -  把导致失败的停止信号设为 1，递归执行第 4 步。

6. 如果第 4 步成功：输出转移

最后，用生成的转移表创建 `$fsm` 单元并加入模块。这个新单元连接到控制信号，同时
断开控制输出原来的驱动源。

FSM 优化
~~~~~~~~


`fsm_opt` pass 对 `$fsm` 单元执行基本优化（不包括状态重新编码）。以下优化按此顺序
执行：

-  从 `$fsm` 单元中删除未使用的控制输出。

-  连接到同一驱动源的控制输入会被合并。

-  当某个控制输入由某个控制输出驱动时，删除该控制输入，并修改转移表，使得在没有
   外部反馈路径的情况下仍具有相同的行为。

-  转移表中输出相同、仅在单个控制输入位上取值不同的条目会被合并，同时把该不同的位
   从敏感列表中删除（变为无关位）。

-  删除常量输入，并修改转移表以保持行为不变。

-  删除未使用的输入。

FSM 重新编码
~~~~~~~~~~~~


`fsm_recode` pass 为各个状态分配新的位模式。通常这还意味着状态信号宽度的变化。
在撰写本文时，只支持独热编码，且复位状态为全零。

`fsm_recode` pass 还可以把它所做的改动写入文本文件，在使用 Synopsys Formality
验证由 Yosys 综合的设计时可以使用该文件。
