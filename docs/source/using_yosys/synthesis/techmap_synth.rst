技术映射
========


.. todo:: 少些学术腔，检查文字是否连贯

前面几章概述了 HDL 代码如何转换为 RTL 网表。RTL 网表仍然基于抽象的粗粒度单元
类型，例如任意宽度的加法器甚至乘法器。本章介绍如何把 RTL 网表转换为功能等价的
网表，其中使用目标架构中可用的单元类型。

技术映射通常分两个阶段进行。第一阶段把 RTL 单元映射到单比特单元构成的内部库
（参见 :ref:`sec:celllib_gates`）。第二阶段把这个由内部门类型构成的网表转换为由
目标工艺库中的门构成的网表。

当目标架构提供粗粒度单元（例如块 RAM 或 ALU）时，必须在 RTL 网表中直接映射这些
单元，因为设计一旦被映射为按位宽的门类型，其粗粒度结构的信息就会丢失。

单元替换
--------


最简单的技术映射形式是单元替换，techmap pass（处理流程）就是做这件事的。当向这个
pass 提供一个用更简单的单元实现 RTL 单元类型的 Verilog 文件时，它会直接用所提供的
实现替换 RTL 单元。

如果没有提供映射文件，techmap 会使用一个内置映射文件，把 Yosys 的 RTL 单元类型
映射到 Yosys 使用的内部门库。好奇的读者可以在 Yosys 源码树中的
:file:`techlibs/common/techmap.v` 找到这个映射文件。

techmap 还加入了一些附加特性，以支持对单元进行条件映射（参见
:doc:`/cmd/index_passes_techmap`）。例如，当目标架构支持某些位宽的硬件乘法器而
不支持其他位宽时，这就会很有用。

典型的综合流程会先用 techmap pass 把一些 RTL 单元直接映射为目标架构提供的粗粒度
单元（如果有的话），然后用内置默认文件运行 techmap，把其余 RTL 单元映射为门级
逻辑。

子电路替换
----------


有时目标架构提供的单元比 Yosys 使用的 RTL 单元更强大。例如，目标架构中某个能计算
两个数绝对差的单元，并不对应任何单一的 RTL 单元类型，只对应多个单元的组合。

对于这些情况，Yosys 提供了 extract pass，它可以把给定的一组模块与设计进行匹配，
找出设计中与给定模块中任意一个相同（即同构子电路）的部分。随后这些匹配到的子电路
会被替换为给定模块的实例。

extract pass 还能找出给定模块的基本变体，例如可交换单元类型上被交换的输入。

除此之外，extract pass 还对频繁子电路挖掘提供有限支持，即在设计中寻找重复出现
子电路的过程。这有一些应用，包括设计新的粗粒度架构
:cite:p:`intersynthFdlBookChapter`。

extract pass 所完成的繁重算法工作（求解同构子电路问题和频繁子电路挖掘）是由
SubCircuit 库完成的，该库也可以脱离 Yosys 独立使用（参见 :ref:`sec:SubCircuit`）。

门级技术映射
------------


.. todo:: 较新的 techmap 库似乎大多是 ``.v`` 而不是 ``.lib``

在门级，目标架构通常由“Liberty 文件”描述。Liberty 文件格式是一种行业标准格式，
可用于描述标准库单元的行为及其他属性。

把使用了 Yosys 内部门库的设计（例如使用 techmap pass 映射到这种表示后的结果）
进行映射，分两个阶段完成。

首先，必须把寄存器单元映射到目标架构上可用的寄存器。目标架构可能并不提供具有正
时钟沿和负时钟沿、高有效和低有效异步置位和/或复位等各种组合的 D 型触发器。因此，
映射寄存器的过程可能会向设计中加入额外的反相器，所以先映射寄存器单元很重要。

寄存器单元的映射可以使用 dfflibmap pass 完成。这个 pass 期望把一个 Liberty 文件
作为参数（使用 -liberty 选项），并且只使用 Liberty 文件中的寄存器单元。

其次，必须把组合逻辑映射到目标架构。这通过 abc pass 使用外部程序 ABC 来完成，
具体做法是给该 pass 传入 -liberty 选项。注意在这种情况下，只会用到单元库中的
组合单元。

有时 Liberty 文件包含不能自由共享的商业秘密（例如敏感的时序信息）。这会使报告
相关工具中的 bug 等流程变得复杂。如果 Yosys 和 ABC 所用的 Liberty 文件中的信息
不属于敏感信息，则可以使用附加工具 yosys-filterlib（参见 :ref:`sec:filterlib`）
从 Liberty 文件中剥离敏感信息。
