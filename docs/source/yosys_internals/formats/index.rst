内部格式
========


Yosys 使用两种不同的内部格式。第一种用于存储 Verilog 输入文件的抽象语法树（AST）。
这种格式直接称为 AST，由 Verilog 前端生成。该数据结构由称为 AST 前端的子系统
读取 [1]_。随后 AST 前端生成 Yosys 主要内部格式的设计，即寄存器传输级中间语言
（RTLIL）表示。它首先在 AST 表示上执行若干化简，然后根据化简后的 AST 数据结构
生成 RTLIL。

所有 pass 都以 RTLIL 表示作为输入和输出。与在不同 pass 之间使用不同表示格式相比，
这样做有以下优点：

-  可以按不同顺序重新排列 pass，也可以删除或插入 pass。

-  pass 可以直接原样传递设计中它们不改变的部分，而不需要在格式之间转换。事实上，
   Yosys 的 pass 输出它们收到的那份数据结构，并且原地完成所有修改。

-  所有 pass 使用相同的接口，因此在阅读 Yosys 源码时（例如添加新特性时）可以减少
   理解某个 pass 所需的工作量。

RTLIL 表示基本上是一种网表表示，另外还支持以下特性：

-  内部单元库，包含表示 RTL 数据通路和寄存器单元的固定功能单元，以及逻辑门级单元
   （单比特门和寄存器）。

-  支持多比特值，既可以取信号线的各个位，也可以取常量位，用来表示粗粒度网表。

-  支持基本的行为级构造（if-then-else 结构，以及带用于更新输出的敏感列表的多分支
   switch）。

-  支持多端口存储器。

使用 RTLIL 也有缺点：在所有 pass 之间都要使用一种非常强大的格式，即使在进行门级
综合、并不需要更高级特性时也是如此。为了降低作用于低层表示的 pass 的复杂度，这些
pass 会检查输入 RTLIL 中使用的特性，并在遇到不受支持的高层构造时拒绝运行。在这种
情况下，必须先由综合脚本调用某个把高层构造转换为低层构造的 pass。
